# BreatheFresh Architecture & Technical Design

## 1. System Overview

BreatheFresh is a privacy-first, hyper-local clean air intelligence application engineered for Indian families and communities during severe winter smog episodes (GRAP I–IV). It translates complex atmospheric pollution data into personalized, actionable daily protection protocols and quantifiable health metrics (cigarette-equivalent inhalation doses).

## 2. Core Architectural Pillars

### 2.1 Deterministic Impact Engine vs. Generative AI
- **Strict Separation of Concerns:** In accordance with TRD Section 6.5, **no mathematical calculation, exposure index, or cigarette-equivalent claim is ever generated by the LLM.**
- All numbers are computed on the client inside `src/engine/` via deterministic physical equations.
- The LLM's role is strictly confined to natural language formatting, empathetic tone, and localized contextual explanations (English, Hindi, Hinglish).

### 2.2 Number Guard Verification
- Every LLM-generated response passes through the `NumberGuard` (`src/engine/numberGuard.ts`) before being displayed to the user.
- The Number Guard extracts all numeric tokens from the LLM output and validates them against a strict whitelist of engine-computed numbers (AQI, PM2.5, member doses, action deltas, and clock hours).
- Any sentence containing an unverified or hallucinated number is replaced with a trusted engine fallback phrase (`"Impact calculated by engine."`).

### 2.3 Anonymous Identity & Zero Authentication
- In compliance with project privacy rules, **no authentication SDK (`firebase/auth`), passwords, cookies, or user PII are used.**
- Identity is managed entirely via an anonymous RFC4122 v4 UUID generated on the client and stored in `localStorage` (`src/lib/deviceId.ts`).
- If Firestore is offline or unconfigured, the application operates with 100% functionality using local state.

## 3. Impact Engine Mathematical Foundations

### 3.1 Indoor Concentration Mass Balance
Indoor PM2.5 concentrations ($C_{in}$) are derived hourly using steady-state mass balance:

$$C_{in} = \frac{P \cdot a \cdot C_{out}}{a + k + \frac{CADR}{V}} + S_{sources}$$

Where:
- $P$: Penetration efficiency factor (0.80 closed, 0.40 sealed, 1.0 open windows).
- $a$: Air changes per hour (ACH).
- $k$: Natural particulate deposition rate ($0.2\ \text{h}^{-1}$).
- $CADR$: Clean Air Delivery Rate of the purifier ($\text{m}^3/\text{h}$).
- $V$: Volume of room / home ($\text{Area} \times 2.8\text{m}$).
- $S_{sources}$: Internal particulate additions (e.g., cooking: $+35\ \mu\text{g}/\text{m}^3$, agarbatti: $+50\ \mu\text{g}/\text{m}^3$).
- **Safety Clamp:** $C_{in} \ge 0.05 \cdot C_{out}$ (minimum 5% physical bypass floor).

### 3.2 Individual Exposure Index (EI) & Cigarette Equivalents
For each household member, 24-hour breathing-weighted inhalation dose is modeled:

$$EI = \frac{\sum_{h=0}^{23} C(h) \cdot B(h) \cdot (1 - M(h))}{\sum_{h=0}^{23} B(h)}$$

Where:
- $C(h)$: Ambient concentration at the member's location during hour $h$ (home, commute, work/school).
- $B(h)$: Minute ventilation rate multiplier based on activity (rest: 0.8, light: 1.0, moderate: 1.6, exercise: 3.2).
- $M(h)$: Mask filtration efficiency (none: 0%, surgical: 20%, cloth: 10%, N95: 80% fitted).

The cumulative daily toxic dose is converted to cigarette equivalents using the Berkeley Earth heuristic:

$$\text{Cigarette Equivalents} = \frac{EI}{22\ \mu\text{g}/\text{m}^3}$$

## 4. Multi-Tiered Fallback Hierarchy

Every external dependency in BreatheFresh is designed with deterministic local fallbacks:

| Service / Layer | Failure Mode | Graceful Recovery Mechanism | User Visibility |
|---|---|---|---|
| **Open-Meteo Air API** | 500, 429, Timeout (>6s), Offline | Falls back to nearest geographic offline sample snapshot (`getNearestFallback`) | Amber badge: *"Sample Data (API Offline)"* with live retry |
| **Groq /api/plan** | Timeout (>12s), 429, 503, Invalid JSON, Missing Key | In-browser deterministic rule-based planner (`src/engine/plannerFallback.ts`) | Teal banner: *"Rule-Based Action Plan — Impact Engine Verified"* |
| **Firebase Firestore** | Network down, permission denied, unconfigured | Silent fallback; all state preserved in Zustand and `localStorage` | Seamless; community forms show offline notice |
| **Speech Recognition** | Browser unsupported, permission denied | Manual text input and quick suggestion chips | Native fallback input |

## 5. Security & Threat Model

1. **Serverless AI Boundary:** `GROQ_API_KEY` is strictly confined to server-side Node.js functions (`api/`). Zero AI vendor client SDKs exist in the frontend bundle.
2. **Rate Limiting:** Sliding-window in-memory rate limiting (20 requests/minute per IP) on all serverless endpoints (`api/_lib/rateLimit.ts`).
3. **Strict Input Validation:** All API inputs are validated using Zod schemas (`PlanInputSchema`, `ChatInputSchema`, `ExplainInputSchema`, `VisionInputSchema`). Payloads larger than 10KB are rejected with HTTP 400.
4. **Architectural Guardrails in CI:** `scripts/check-constraints.js` runs on every commit and PR to prevent accidental inclusion of `firebase/auth`, client-side API keys, or unauthorized dependencies.
